## 1. 먼저 읽기 — 이 보스는 어떤 전투인가

Boss04를 처음 보는 사람은 아래 내용부터 이해하면 된다.

이 보스전의 핵심은 **Guard를 피해 도망쳐서 전투를 끝내는 것이 아니라, 끝까지 따라오는 Guard의 공격을 피한 뒤 공격 직후 열린 약점을 Rope Impact로 반복 타격해 직접 처치하는 것**이다.

전투는 크게 세 부분으로 나뉜다.

```text
1단계 — Guard A
플레이어보다 높은 위치에서 추격
→ 다음 착지점 여러 곳을 범위 폭발로 압박
→ 공격이 끝나면 뒤쪽 후방 추진기 약점 개방
→ 플레이어가 뒤쪽으로 돌아 Rope Impact
→ HP 0까지 반복

2단계 — Guard B
플레이어와 비슷한 높이에서 추격
→ 다음 착지점 한 곳을 먼저 선점하도록 돌진
→ 돌진이 끝나면 측면 제어기 약점 개방
→ 플레이어가 측면으로 돌아 Rope Impact
→ HP 0까지 반복

3단계 — 중앙 보안 허브
Guard A/B가 모두 죽기 전까지 보호막 유지
→ 방향성 빔과 착지점 범위 폭발로 P3 이동 경로 압박
→ 두 Guard가 모두 죽으면 보호막 해제
→ 공격 한 사이클이 끝난 뒤 중앙 코어 개방
→ 플레이어가 Rope Impact
→ HP 0이면 보스전 종료
```

즉 플레이어가 이 보스에서 반복하는 행동은 다음과 같다.

```text
추격당함
→ 공격 예고를 읽음
→ Rope로 안전한 위치로 이동
→ 공격 회피
→ 약점이 열린 방향으로 다시 이동
→ Rope Impact
→ 다시 추격당함
```

Guard A와 Guard B는 **한 번 발각되면 HP가 0이 될 때까지 스스로 추격을 포기하지 않는다.**

따라서 플레이어가 Guard A를 죽이지 않고 다음 구역으로 이동하면 Guard A가 그대로 따라온다.
그 상태에서 Guard B까지 발각하면 두 Guard가 동시에 추격한다.
두 Guard가 살아 있는 상태로 P3에 들어가면 중앙 보안 허브까지 활성화되어 세 적이 동시에 공격할 수 있다.

## 2. 핵심 요소 — 반드시 이해해야 하는 6가지

### 2.1 한번 발각된 Guard는 죽을 때까지 따라온다

발각된 Guard는 다음 이유로 전투를 끝내지 않는다.

- 플레이어가 원래 전투 구역을 벗어남
- 시야가 벽이나 구조물에 가려짐
- 플레이어가 Refuge Landing에 들어감
- 플레이어가 다음 전투 구역으로 이동함
- 플레이어와 Guard 사이 거리가 크게 벌어짐

Guard의 추격을 끝내는 전투 내 조건은 하나다.

```text
Guard HP <= 0
```

플레이어가 죽고 재시도할 때만 살아 있던 Guard의 HP와 전투 상태가 초기화된다.

### 2.2 Guard의 공격 중에는 때리지 말고, 공격 직후 약점을 노린다

두 Guard 모두 공격을 실제로 실행하는 동안은 완전 무적이다.

```text
공격 예고
→ 공격 실행: Guard 피해 0
→ 공격 종료
→ 약점 개방
→ Rope Impact 가능
```

Guard A는 **후방 추진기**, Guard B는 **측면 제어기**가 열린다.

약점은 플레이어를 향해 자동으로 돌아오지 않는다.
플레이어가 Rope 이동으로 Guard의 뒤쪽 또는 측면으로 직접 돌아가야 한다.

### 2.3 Guard A와 Guard B는 같은 추격자가 아니다

둘의 차이는 공격 모양이 아니라 **플레이어 이동을 막는 방식**이다.

**Guard A**
- 플레이어보다 위쪽을 따라감
- 플레이어가 다음에 착지할 수 있는 위치 여러 곳을 미리 표시
- 표시된 위치를 순서대로 폭발
- 플레이어가 한 착지점에 오래 머무르지 못하게 만듦

**Guard B**
- 플레이어와 비슷한 높이를 따라감
- 플레이어가 다음에 착지할 가능성이 높은 위치 한 곳을 선택
- 그 위치로 직접 돌진
- 플레이어가 원래 생각한 착지 경로를 바꾸게 만듦

따라서 Guard A는 **여러 착지 선택지를 줄이는 적**, Guard B는 **한 착지점을 먼저 차지하는 적**이다.

### 2.4 Guard를 건너뛰면 전투가 사라지는 것이 아니라 겹친다

P1, P2, P3 사이에 Guard 처치 여부로 닫히는 전투문을 두지 않는다.

예:

```text
Guard A를 안 죽이고 P2 진입
→ Guard A 계속 추격
→ Guard B 발각
→ A+B 동시전

A/B를 안 죽이고 P3 진입
→ A/B 계속 추격
→ 중앙 보안 허브 활성화
→ A+B+Hub 동시전
```

게임은 이 상황을 자동으로 쉽게 만들어 주지 않는다.

- 다른 적이 공격 중이라고 공격을 기다리지 않음
- 한 번에 한 적만 공격하도록 조정하지 않음
- 겹친 공격을 자동 취소하지 않음

따라서 선행 Guard를 먼저 처치하는 것이 기본 진행이며, 건너뛰기는 플레이어가 선택한 고난도 진행이 된다.

### 2.5 중앙 보안 허브는 Guard를 살려둔 상태에서는 파괴할 수 없다

Guard A/B는 각각 중앙 보안 허브의 보호 링크 하나를 유지한다.

```text
Guard A 생존
→ 보호 링크 A 활성

Guard B 생존
→ 보호 링크 B 활성

보호 링크 A 또는 B 중 하나라도 활성
→ 중앙 보안 허브 보호막 활성
→ 코어 닫힘
→ Hub 피해 0
```

따라서 플레이어가 P3까지 먼저 도착했더라도 결국 살아 있는 Guard를 처치해야 한다.

두 Guard가 모두 죽으면:

```text
보호 링크 A 해제
+
보호 링크 B 해제
→ 중앙 보안 허브 보호막 해제
```

그 뒤 Hub의 현재 공격 한 사이클이 끝나면 코어가 열린다.

### 2.6 사망하면 완료한 전투만 남고, 진행 중이던 전투는 초기화된다

예:

```text
Guard A 처치 완료
→ Guard B 전투 중 사망
```

재시도 시:

```text
Guard A = 사망 유지
보호 링크 A = 해제 유지
Guard B = HP와 전투 상태 초기화
플레이어 = Refuge Landing에서 부활
```

즉 이미 끝낸 Guard 전투를 다시 반복하지 않지만, 살아 있던 적의 HP를 사망을 이용해 조금씩 깎아 누적할 수는 없다.

## 3. 설계 우선순위

아래 순서는 Boss04를 구현하거나 수정할 때 **무엇을 먼저 지켜야 하는지**를 나타낸다.
아래 항목끼리 충돌하면 숫자 조정보다 위쪽 항목을 우선한다.

### 1순위 — Rope 이동이 공격과 반격의 중심이어야 한다

플레이어의 기본 해결 방법은 별도 무기나 상호작용 버튼이 아니다.

```text
Rope로 이동
→ 공격 회피
→ 약점 방향으로 위치 변경
→ 속도 확보
→ Rope Impact
```

Guard와 Hub 모두 기본 Rope Impact만으로 처치 가능해야 한다.

### 2순위 — 공격 예고를 보고 피할 수 있어야 한다

모든 주요 공격은 다음 순서를 지킨다.

```text
공격 위치 또는 방향 표시
→ 표시된 내용 고정
→ 실제 공격
```

경고가 시작된 뒤 플레이어를 계속 따라가며 공격 위치를 바꾸지 않는다.

플레이어가 공격에 맞았을 때는 “운이 나빠서 맞았다”가 아니라 **경고를 보고도 해당 위치에 남았거나, 이동 선택을 잘못했기 때문**이라고 이해할 수 있어야 한다.

### 3순위 — 공격 직후 반격 위치가 명확해야 한다

공격이 끝나면 약점이 시각적으로 실제로 열린다.

Guard A:
- 뒤쪽 장갑 열림
- 후방 추진기 발광

Guard B:
- 측면 패널 열림
- 측면 제어기 발광

시각적으로 닫혀 있는데 공격 판정만 열리거나, 시각적으로 열려 있는데 피해가 들어가지 않는 상태를 만들지 않는다.

### 4순위 — Guard A와 Guard B의 역할 차이를 유지한다

난이도를 올린다고 두 Guard 모두 플레이어 몸체를 직접 추적 돌진하는 적으로 바꾸지 않는다.

- Guard A = 여러 착지점 압박
- Guard B = 한 착지점 선점

이 차이가 사라지면 Boss04의 전투 구성이 무너진다.

### 5순위 — 선행 Guard를 무시한 결과를 그대로 유지한다

Guard를 건너뛰었을 때 게임이 자동으로 이전 Guard를 제거하거나 공격을 멈추지 않는다.

A+B 또는 A+B+Hub 동시전은 허용한다.

단, 정상적인 순서로 A와 B를 각각 처치한 플레이어에게까지 불필요한 동시 공격을 강요해서는 안 된다.

### 6순위 — 기존 게임 시스템을 최대한 유지한다

현재 게임에 있는 다음 기능은 새로 만들지 않고 우선 재사용한다.

- Rope Impact
- Enemy HP/사망
- Pursuit 이동
- 고정 좌표 범위 공격
- 부활 지점
- 진행 저장
- Boss 피해/약점 판정

Boss04만을 위해 기존 일반 적 전체의 행동을 바꾸지 않는다.

| Guard A | 상부 추격 | 다음 착지점 2~3곳을 순차 폭발시켜 이동 선택지 축소 | 뒤쪽 후방 추진기 | 보호 링크 A 해제 |

**“중앙에서 움직이지 않고 P3의 이동 경로를 빔과 폭발로 막으며, 두 Guard가 모두 죽은 뒤 공격 사이클이 끝날 때만 코어가 열린다.”**

## 5. 플레이어가 실제로 경험하는 전투 순서

### 5.1 정상 진행

```text
P1 진입
→ Guard A 발각
→ Guard A 공격 회피
→ 후방 추진기 타격 반복
→ Guard A 처치
→ Refuge Landing에서 부활 지점 갱신

P2 진입
→ Guard B 발각
→ Guard B 돌진 회피
→ 측면 제어기 타격 반복
→ Guard B 처치
→ P3 진입 전 부활 지점 갱신

P3 진입
→ 중앙 보안 허브 활성화
→ 빔 회피
→ 착지점 범위 폭발 회피
→ 코어 개방
→ Rope Impact 반복
→ Hub HP 0
→ 보호 게이트 자동 개방
```

### 5.2 Guard A를 건너뛴 진행

```text
Guard A 발각
→ Guard A를 죽이지 않고 P2 진입
→ Guard B 발각
→ A+B 동시에 추격

이 상태에서 사망
→ Guard A/B 둘 다 초기화
→ Guard A 미처치이므로 P1 진입 전 부활 지점에서 재시작
```

### 5.3 Guard A만 처치하고 Guard B를 건너뛴 진행

```text
Guard A 처치
→ Refuge Landing 저장
→ Guard B 발각
→ Guard B를 죽이지 않고 P3 진입
→ Hub 활성화
→ Guard B + Hub 동시전

사망
→ Guard A 처치 상태 유지
→ Guard B 초기화
→ Hub 초기화
→ Refuge Landing에서 부활
```

### 5.4 두 Guard를 모두 처치한 정상 P3 전투

```text
Guard A 사망
Guard B 사망
보호 링크 A/B 해제
→ P3 진입
→ Hub 보호막 해제 상태
→ 빔
→ 착지점 범위 폭발
→ 코어 개방
→ Rope Impact
→ 반복
→ Hub 파괴
```

## 6. Boss04 전체 진행 구조

공간 순서는 다음과 같다.

```text
P1 — Guard A 전투 구역
↓
Refuge Landing
↓
P2 — Guard B 전투 구역
↓
P3 — 중앙 보안 허브 전투 구역
↓
보호 게이트
↓
Sector05 방향
```

### 6.1 구역 이동 제한

P1, Refuge Landing, P2, P3 사이에는 **Guard 처치 여부로 생성되는 임시 벽이나 투명 장벽을 두지 않는다.**

즉 플레이어는:

- Guard A를 죽이지 않고 P1을 지나 Refuge Landing으로 갈 수 있다.
- Guard A를 죽이지 않고 P2까지 갈 수 있다.
- Guard A와 Guard B를 모두 죽이지 않고 P3까지 갈 수 있다.

단, **구역을 통과했다고 해당 Guard의 전투가 끝나지는 않는다.**

예:

```text
Guard A 발각
→ 플레이어가 P1을 빠져나감
→ Guard A 추격 유지

플레이어가 P2 진입
→ Guard B도 발각
→ Guard A + Guard B 동시 추격

플레이어가 P3 진입
→ 중앙 보안 허브 활성화
→ 살아 있는 Guard A/B도 계속 추격
```

### 6.2 선행 Guard를 무시했을 때의 처리

선행 Guard를 무시한 경우 게임은 다음과 같은 보정 기능을 넣지 않는다.

- Guard A 공격을 잠시 멈추지 않는다.
- Guard B 공격을 기다리게 하지 않는다.
- 중앙 보안 허브가 Guard 전투 종료를 기다리도록 만들지 않는다.
- 세 적의 공격 순서를 자동으로 나누지 않는다.
- “동시 공격 금지” 토큰을 두지 않는다.

따라서 Guard A, Guard B, 중앙 보안 허브가 동시에 활성화된 경우 각자 독립적으로 공격할 수 있다.

---

## 7. Guard 공통 전투 상태

Guard A와 Guard B는 다음 상태 흐름을 사용한다.

```text
미발각
→ 발각
→ 추격
→ 공격 예고
→ 공격 실행
→ 회복 및 약점 노출
→ 추격 복귀
→ 반복
→ HP 0
→ 사망
```

### 7.1 미발각 상태

미발각 Guard는:

- 맵에 실제 오브젝트로 존재한다.
- 화면에 보일 수 있다.
- 플레이어를 추격하지 않는다.
- 공격하지 않는다.
- 약점을 열지 않는다.

### 7.2 발각 조건

다음 둘 중 하나가 발생하면 발각된다.

1. 플레이어가 해당 Guard의 전투 활성 구역에 들어간다.
2. 미발각 Guard가 플레이어의 피해 판정이 성립하는 공격을 먼저 맞는다.

선제공격 처리:

```text
플레이어 Rope Impact 적중
→ 첫 타격 피해 그대로 적용
→ 같은 시점에 Guard 발각
→ 추격 상태 진입
```

첫 타격을 무효화하지 않는다.

### 7.3 발각 후 추격 해제 조건

발각된 Guard는 다음 상황에서도 추격을 유지한다.

- 플레이어가 원래 전투 활성 구역 밖으로 나감
- 플레이어가 Refuge Landing으로 이동
- 플레이어가 다음 전투 구역으로 이동
- 플레이어와 Guard 사이 거리가 크게 벌어짐
- 시야가 건축물에 가려짐

다음 조건만 추격을 종료한다.

```text
Guard HP <= 0
```

플레이어 사망으로 재시도 상태가 시작되면 해당 시도에서 살아 있던 Guard는 초기 상태로 되돌아간다.

## 8. Guard 이동 규칙

### 8.1 기본 이동 방식

Guard A/B는 플랫폼 위를 걸어가거나, 플레이어가 사용한 Rope 경로를 따라 이동하지 않는다.

추격 중에는 공중 이동으로 플레이어를 따라간다.

다음 시스템은 사용하지 않는다.

- 플랫폼별 이동 경로 탐색
- 계단/다리 순서 탐색
- P1→P2 전용 이동 경로
- P2→P3 전용 이동 경로
- 전투 구역 밖으로 나갔을 때 원위치 복귀
- 구역 경계에서 강제 순간이동

### 8.2 기존 지형 충돌 처리

이 문서에서 확정한 것은 **구역 경계와 설계된 이동 경로가 Guard의 추격을 제한하지 않는다는 것**이다.

고형 건축물을 시각적으로 그대로 관통할지 여부는 인터뷰에서 별도 확정하지 않았다.

따라서 구현 기본 원칙은 다음으로 한다.

- 기존 `EnemyObject`의 지형 충돌 처리를 우선 유지한다.
- 이 충돌 처리 때문에 Guard가 다음 구역으로 추격할 수 없는 경우에만 Boss04 전용 예외가 필요한지 검토한다.
- 구현 편의를 이유로 처음부터 모든 벽을 통과하도록 바꾸지 않는다.

### 8.3 플레이어와의 거리 유지

Guard는 추격 중 플레이어 중심점과 계속 겹치도록 이동하지 않는다.

**Guard A**
- 목표 상대 위치는 플레이어보다 위쪽이다.
- 일반 추격 중에는 플레이어 바로 옆이나 플레이어 중심까지 내려오지 않는다.
- Guard A가 플레이어 바로 위나 몸체에 겹치지 않고, 다음 착지점을 경고 화면에 표시할 수 있을 만큼 플레이어와 떨어진 위치에서 이동을 멈추거나 속도를 낮춘다.

**Guard B**
- 목표 상대 위치는 플레이어와 비슷한 높이다.
- 일반 추격 중에는 플레이어 몸체와 계속 겹치지 않는다.
- Guard B는 일반 추격 중에는 플레이어와 겹치지 않는 거리를 유지하고, 돌진 공격이 시작된 경우에만 고정된 목표 착지점까지 빠르게 이동한다.

정확한 거리 수치는 개발자가 플레이 테스트로 조정한다.

거리 판정의 실제 결과는 다음과 같아야 한다.

```text
Guard가 목표 상대 위치보다 너무 멀다
→ 플레이어 쪽으로 이동

Guard가 목표 상대 위치 범위에 들어왔다
→ 일반 추격 속도로 더 붙지 않음
→ 공격 조건을 기다림
```

## 9. Guard A — 상부 추격 / 착지점 범위 폭발

### 9.1 역할

Guard A는 플레이어 바로 위에서 몸으로 들이받는 적이 아니다.

Guard A의 기본 행동은:

1. 플레이어보다 높은 위치를 따라간다.
2. 플레이어가 다음으로 착지할 가능성이 있는 위치를 찾는다.
3. 그 위치 여러 곳을 미리 표시한다.
4. 표시된 위치를 순서대로 폭발시킨다.
5. 공격이 끝난 뒤 후방 약점을 연다.

### 9.2 착지 후보의 의미

“착지 후보”는 임의의 빈 좌표가 아니다.

후보는 현재 맵에서 플레이어가 실제로 발을 디딜 수 있는 다음과 같은 지점을 우선 사용한다.

- 설계된 발판의 상단
- 설계된 착지면
- 현재 이동 방향에서 이어지는 다음 발판
- 현재 Rope 이동으로 접근 가능한 것으로 판정된 발판

후보 판정은 단순히 “플레이어와 400px 이내”만으로 끝내지 않는다.

현재 설계된 이동 연결과 도달 가능 관계 정보가 있으면 이를 우선 사용한다.

미래 플레이어 위치를 프레임 단위로 완전 시뮬레이션하는 시스템은 만들지 않는다.

### 9.3 정상 공격

공격 대상으로 사용할 수 있는 착지 후보가 충분히 있으면:

```text
착지 후보 수집
→ 2~3곳 선택
→ 선택된 위치 전부 경고 표시
→ 공격 순서 표시
→ 경고 시작 시 위치 고정
→ 첫 번째 위치 폭발
→ 짧은 간격
→ 두 번째 위치 폭발
→ 필요 시 세 번째 위치 폭발
```

경고가 시작된 뒤에는:

- 플레이어가 방향을 바꿔도 위치 변경 없음
- 플레이어가 낙하해도 위치 변경 없음
- 플레이어가 다른 발판으로 이동해도 위치 변경 없음

### 9.4 공격 대상으로 사용할 수 있는 착지 후보가 없을 때

착지 후보가 하나도 없으면 Guard A가 공격을 중단한 채 계속 기다리지 않는다.

이 경우:

```text
공격 예고 시작 시점의 플레이어 현재 좌표 저장
→ 그 좌표에 경고 표시
→ 좌표 고정
→ 저장된 좌표에 1회 범위 폭발
```

플레이어가 경고를 본 뒤 이동하면 폭발은 플레이어를 따라오지 않는다.

### 9.5 공격 중 Guard A 본체

범위 폭발 공격이 실제로 실행되는 동안:

- Guard A는 모든 플레이어 공격에 피해를 받지 않는다.
- Rope Impact가 맞아도 HP가 줄지 않는다.
- Rope Impact가 맞아도 범위 폭발이 취소되지 않는다.
- Guard A 몸체와 플레이어가 접촉하면 플레이어가 피해를 받는다.
- 접촉 시 플레이어는 Guard A에서 멀어지는 방향으로 짧게 밀려난다.

범위 폭발이 끝난 뒤에는 본체 접촉 피해를 제거한다.

### 9.6 공격 종료 후 약점

범위 폭발이 끝나면 다음 상태가 동시에 시작된다.

```text
후방 장갑 열림
→ 후방 추진기 노출
→ 약점 충돌 판정 활성
→ 강한 발광
→ 열기/스파크 효과
→ 회복 타이머 시작
→ 저속 추격 시작
```

이때 Guard A는 약점이 플레이어 쪽을 향하도록 자동 회전하지 않는다.

공격이 끝났을 때의 방향을 기준으로 후방 약점이 열린다.

플레이어는 Rope 이동으로 Guard A 뒤쪽 공격 각도를 만들어야 한다.

### 9.7 회복 중 이동

회복 중 Guard A는 정지하지 않는다.

- 플레이어를 계속 목표로 삼는다.
- 일반 추격보다 느린 속도로 이동한다.
- 후방 추진기는 회복 종료까지 계속 열린다.
- 회복 중에는 새로운 범위 폭발을 시작하지 않는다.
- 약점을 맞아도 회복 타이머는 처음부터 다시 시작되지 않는다.
- 약점을 여러 번 맞아도 회복 시간이 늘어나지 않는다.

권장 약점 노출 시간: **약 1.8초**

## 10. Guard B — 경로 차단 / 착지점 선점 돌진

### 10.1 역할

Guard B의 공격 목표는 플레이어 몸체를 계속 추적하는 것이 아니다.

Guard B는:

1. 플레이어와 비슷한 높이에서 따라간다.
2. 플레이어가 다음에 착지할 가능성이 높은 위치 하나를 고른다.
3. 그 위치를 경고한다.
4. 경고가 끝나면 해당 위치로 돌진한다.
5. 돌진 종료 후 측면 약점을 연다.

### 10.2 정상 공격

```text
현재 이동 방향에서 착지 후보 수집
→ 가장 가능성 높은 후보 1곳 선택
→ 선택한 착지점에 경고 표시
→ 위치 고정
→ 해당 위치로 돌진
```

공격 예고에서는 **목표 착지점**을 보여준다.

돌진 전체 경로를 바닥 선으로 표시하는 것은 필수 조건이 아니다.

### 10.3 공격 대상으로 사용할 수 있는 착지 후보가 없을 때

```text
공격 예고 시작 시 플레이어 현재 좌표 저장
→ 해당 좌표 경고
→ 좌표 고정
→ 저장된 좌표를 향해 돌진
```

돌진 시작 후 플레이어 위치가 바뀌어도 방향을 다시 수정하지 않는다.

### 10.4 돌진 중 Guard B 본체

돌진이 실행되는 동안:

- Guard B는 플레이어 공격에 피해를 받지 않는다.
- Rope Impact로 돌진을 끊을 수 없다.
- Guard B 몸체 전체가 플레이어 피해 판정이다.
- 플레이어 충돌 시 피해를 준다.
- 플레이어는 Guard B의 돌진 진행 방향으로 짧게 밀려난다.

돌진이 끝나면 본체 접촉 피해를 제거한다.

### 10.5 공격 종료 후 약점

돌진 종료 시:

```text
돌진 진행 방향 유지
→ 급정지
→ 측면 패널 열림
→ 측면 제어기 노출
→ 약점 충돌 판정 활성
→ 강한 발광
→ 전기/스파크 효과
→ 회복 타이머 시작
→ 저속 추격 시작
```

Guard B도 약점이 플레이어 쪽을 향하도록 자동 회전하지 않는다.

플레이어는 Guard B 측면으로 이동해 Rope Impact 각도를 만들어야 한다.

### 10.6 회복 중 이동

- 플레이어를 계속 따라간다.
- 일반 추격보다 느린 속도 사용
- 새로운 돌진 사용 금지
- 측면 제어기는 회복 종료까지 열린 상태 유지
- 약점 피격으로 회복 시간 연장 없음

권장 약점 노출 시간: **약 1.5초**

## 11. Guard 피해 처리

### 11.1 평상시 본체

추격 중 또는 회복 중 Guard 본체에 Rope Impact가 맞으면 피해는 들어간다.

단, 약점보다 효율이 낮다.

권장 시작값:

```text
본체 피해 효율 = 약점 기준 피해의 약 20~30%
```

정확한 배율은 플레이 테스트로 조정한다.

### 11.2 공격 실행 중

Guard A 범위 폭발 실행 중:

```text
받는 피해 = 0
```

Guard B 돌진 실행 중:

```text
받는 피해 = 0
```

### 11.3 약점

약점 충돌 판정이 열린 동안 해당 약점에 Rope Impact가 맞으면:

- 본체보다 높은 피해 적용
- 약점 추가 피해 적용 가능
- 강한 피격 시각·음향 효과(VFX/SFX)
- Guard 본체 피격 반응 표시

단:

- 회복 타이머 연장 없음
- 추가 stun 없음
- 공격 패턴 단계 변경 없음

### 11.4 사망

Guard HP가 0이 되는 즉시:

```text
현재 공격 중지
→ 해당 Guard의 공격 판정 제거
→ 해당 Guard 충돌 판정 제거
→ 추격 로직 중지
→ Guard 규모의 폭발 시각·음향 효과(VFX/SFX)
→ Guard 오브젝트 제거
→ 해당 보호 링크 해제
```

Guard는 사망 후 Dock으로 돌아가지 않는다.

## 12. 보호 링크

Guard A가 죽으면:

```text
보호 링크 A = 해제
```

Guard B가 죽으면:

```text
보호 링크 B = 해제
```

보호 링크 상태는 **Guard의 사망 여부와 동일한 진행 상태**로 취급한다.

따라서 플레이어가 죽더라도:

- 이미 죽은 Guard는 다시 생성하지 않는다.
- 해당 보호 링크는 해제 상태를 유지한다.

## 13. 사망과 체크포인트

### 13.1 체크포인트 갱신 조건

체크포인트는 플레이어가 특정 좌표를 먼저 밟았다는 이유만으로 갱신하지 않는다.

다음 전투 완료 조건을 충족했을 때만 다음에 지정된 부활 지점을 활성화한다.

```text
Guard A 미처치
→ P1 진입 전 부활 지점에서 부활

Guard A 처치
→ Refuge Landing에서 부활

Guard A + Guard B 처치
→ P3 진입 전 부활 지점에서 부활

중앙 보안 허브 처치
→ Boss04 완료 상태 유지
→ 보호 게이트 열린 상태 유지
```

### 13.2 살아 있던 적의 초기화

플레이어 사망 시 그 시점에 살아 있던 적은 이번 전투 진행을 유지하지 않는다.

살아 있던 Guard:

- HP 최대치로 복구
- 공격 상태 초기화
- 발각 상태 초기화
- 원래 재시작 위치로 복귀

중앙 보안 허브:

- 중앙 보안 허브 HP 최대치로 복구
- 진행 중 빔/범위 폭발/코어 상태 제거
- 새 P3 진입 전 상태로 복구

이미 죽은 Guard는 복구하지 않는다.

### 13.3 예시

Guard A만 처치한 뒤 B와 중앙 보안 허브를 동시에 상대하다 사망:

```text
Guard A = 사망 유지
보호 링크 A = 해제 유지

Guard B = HP/상태 초기화
중앙 보안 허브 = HP/공격 상태 초기화

플레이어 = Refuge Landing에서 부활
```

Guard A/B 모두 처치한 뒤 중앙 보안 허브와 싸우다 사망:

```text
Guard A/B = 사망 유지
보호 링크 A/B = 해제 유지
중앙 보안 허브 = HP/공격 상태 초기화
플레이어 = P3 진입 전 부활 지점에서 부활
```

## 14. Refuge Landing 동작 규칙

Refuge Landing은 **플레이어가 들어왔다는 이유만으로 Guard의 발각이나 추격 상태를 지우는 구역이 아니다.**

### 14.1 Guard A를 먼저 처치한 경우

```text
Guard A 사망
→ 보호 링크 A 해제
→ 플레이어 Refuge Landing 진입
```

이 상태에서는:

- Guard A가 존재하지 않으므로 A 공격 없음
- Guard B는 P2 발각 조건이 발생하기 전까지 미발각
- 중앙 보안 허브는 P3에 진입하기 전까지 비활성
- 따라서 Refuge Landing에서 플레이어를 공격하는 Boss04 적이 없음

이 경우에만 Refuge Landing을 **Boss04 적의 공격 판정이 발생하지 않는 재정비 구간**으로 취급한다.

### 14.2 Guard A를 처치하지 않고 들어온 경우

```text
Guard A 발각 상태
→ 플레이어가 P1을 이탈
→ Refuge Landing 진입
```

이때:

- Guard A의 발각 상태 유지
- Guard A 추격 유지
- Guard A 공격 타이머 유지 또는 현재 상태기계의 순서에 따라 계속 진행
- Guard A의 범위 폭발 사용 가능
- Guard A가 죽기 전까지 Refuge Landing도 전투 공간으로 취급

Refuge Landing 진입 자체는 다음을 수행하지 않는다.

- Guard A 추격 해제
- Guard A 위치 초기화
- Guard A HP 회복
- Guard A 공격 취소
- Guard A 약점 강제 닫기
- Guard A를 P1으로 순간이동

### 14.3 Guard B 발각

Guard B는 Refuge Landing에 들어왔다는 이유만으로 자동 발각되지 않는다.

Guard B의 지정된 P2 활성 구역에 들어가거나 Guard B를 먼저 공격했을 때 발각된다.

## 15. Guard A와 Guard B가 동시에 살아 있을 때

Guard A를 죽이지 않고 P2 활성 구역에 들어가면:

```text
Guard A = 이미 발각, 추격 계속
Guard B = 새로 발각
```

이후 두 Guard는 서로의 상태를 확인하지 않고 각각 상태기계를 진행한다.

예:

```text
Guard A 범위 폭발 예고
+
Guard B 돌진 예고
```

동시에 가능.

```text
Guard A 범위 폭발 실행
+
Guard B 돌진 실행
```

동시에 가능.

### 15.1 공격 순서 조정 없음

다음 기능을 넣지 않는다.

- A가 공격 중이면 B 공격 대기
- B가 공격 중이면 A 공격 대기
- 한 번에 한 Guard만 공격
- 두 Guard 공격 사이 최소 안전시간 강제
- 플레이어가 특정 위치에 있을 때 한쪽 공격 자동 취소

### 15.2 적군 간 피해 없음

Guard A의 범위 폭발은:

- 플레이어에게만 피해
- Guard B에게 피해 없음
- 중앙 보안 허브에게 피해 없음

Guard B의 돌진 피해는:

- 플레이어에게만 적용
- Guard A에게 피해 없음
- 중앙 보안 허브에게 피해 없음

### 15.3 적군 간 물리 충돌 없음

Guard A와 Guard B는 서로를 이동 장애물로 사용하지 않는다.

- 서로 밀어내지 않음
- 서로의 이동을 멈추지 않음
- 서로 충돌해서 돌진/범위 폭발 상태가 취소되지 않음

중앙 보안 허브도 Guard의 이동을 막지 않는다.

## 16. P3 — 중앙 보안 허브

### 16.1 위치와 이동

중앙 보안 허브는 P3 중앙의 고정 시설이다.

- 추격하지 않는다.
- 플레이어 위치로 이동하지 않는다.
- Guard처럼 자유 비행하지 않는다.
- 공격할 때도 중앙 위치를 유지한다.

중앙 보안 허브가 변화시키는 것은 자신의 위치가 아니라 **P3 내 공격 위험 구역**이다.

### 16.2 활성화 조건

플레이어가 P3 전투 활성 구역에 처음 들어가면 중앙 보안 허브가 활성화된다.

Guard A/B 생존 여부는 중앙 보안 허브 활성화를 막지 않는다.

예:

```text
Guard A 생존
Guard B 생존
플레이어 P3 진입
→ 중앙 보안 허브 활성화
```

이후:

- Guard A 추격 계속
- Guard B 추격 계속
- 중앙 보안 허브 공격 시작 가능

### 16.3 P3 밖으로 나갔을 때

플레이어가 P3 전투 구역 밖으로 이동하면 중앙 보안 허브는 다음을 즉시 수행한다.

- 빔 경고 제거
- 실행 중 빔 피해 판정 제거
- 범위 폭발 경고 제거
- 실행 중 범위 폭발 피해 판정 제거
- 코어가 열려 있으면 즉시 닫음
- 현재 공격 단계 폐기

유지하는 값:

- 중앙 보안 허브가 한 번 활성화되었다는 상태
- 중앙 보안 허브 HP
- 보호 링크 A/B 상태
- 보호막 활성/해제 상태

플레이어가 다시 P3 안으로 들어오면 이전 공격의 남은 시간을 이어서 사용하지 않는다.

```text
재진입
→ 새 빔 후보 계산
→ 새 빔 경고부터 시작
```

Guard A/B는 플레이어가 P3 밖으로 나가도 계속 플레이어를 추격한다.

## 17. 중앙 보안 허브 보호막과 보호 링크

### 17.1 Guard가 하나라도 살아 있을 때

예:

```text
A 생존, B 사망
→ 보호 링크 A 활성
→ 보호 링크 B 해제
→ 중앙 보안 허브 보호막 활성
```

또는:

```text
A 사망, B 생존
→ 보호 링크 A 해제
→ 보호 링크 B 활성
→ 중앙 보안 허브 보호막 활성
```

보호막 활성 동안:

- 중앙 보안 허브는 빔/범위 폭발 공격 가능
- 코어는 열리지 않음
- 중앙 보안 허브 본체/코어에 Rope Impact가 맞아도 피해 0
- 플레이어는 살아 있는 Guard를 먼저 죽여야 중앙 보안 허브 피해 가능 상태를 만들 수 있음

### 17.2 Guard A/B 모두 죽었을 때

```text
보호 링크 A 해제
보호 링크 B 해제
→ 중앙 보안 허브 보호막 해제
```

보호막이 꺼지는 시각 효과는 즉시 반영한다.

단, 마지막 Guard가 죽은 순간 중앙 보안 허브 공격이 이미 진행 중이라면:

- 이미 시작된 빔/범위 폭발은 즉시 취소하지 않는다.
- 해당 공격 단계가 끝날 때까지 예고된 순서대로 끝까지 실행한다.
- 그 공격이 끝난 뒤 코어 개방 단계로 넘어간다.

## 18. 중앙 보안 허브 공격 사이클

중앙 보안 허브의 한 공격 주기는 다음과 같다.

```text
방향성 빔
→ 플레이어 위치 재확인
→ 착지점 범위 폭발
→ 보호막 해제라면 코어 개방
→ 코어 닫힘
→ 다음 빔
```

보호막 활성이면 범위 폭발 이후 코어를 열지 않고 다음 빔 주기로 넘어간다.

## 19. 방향성 빔

### 19.1 사용할 수 있는 방향

빔은 P3 전투 공간에 미리 정한 세 방향만 사용한다.

```text
LEFT
RIGHT
UPPER
```

빔이 플레이어를 향해 자유 각도로 회전하지 않는다.

### 19.2 빔 선택

빔을 고를 때 중앙 보안 허브는 현재 플레이어 위치를 기준으로 세 후보를 검사한다.

각 빔 후보에 대해:

1. 그 빔의 실제 피해 영역을 적용한다고 가정한다.
2. 플레이어가 현재 위치에서 이동할 수 있는 설계된 이동 경로와 착지점 중 빔 피해 영역 밖에 남는 경로가 있는지 확인한다.
3. 최소 한 경로가 남는 빔만 선택 후보로 인정한다.

여기서 검사하는 위험 요소는 **중앙 보안 허브 빔 자체만**이다.

Guard A/B의 현재 위치나 공격 경고는 계산에 넣지 않는다.

따라서:

```text
중앙 보안 허브의 빔만 보면 왼쪽 이동 경로에 피해 판정이 없음
하지만 Guard B가 왼쪽 경로 돌진 중
```

같은 상황은 발생할 수 있다.

이 경우 중앙 보안 허브가 빔을 취소하거나 다른 방향으로 다시 계산하지 않는다.

### 19.3 직전 방향 반복

빔 자체만 고려했을 때 회피 경로가 남는 빔 후보가 둘 이상이면 직전에 사용한 방향을 제외한 후보를 우선 선택한다.

직전 방향만 빔 자체 기준 회피 경로를 남기는 경우에는 같은 방향을 다시 사용할 수 있다.

우선순위:

```text
1. 중앙 보안 허브 빔 단독으로 회피 가능한 방향
2. 그중 직전 방향이 아닌 방향
3. 다른 회피 가능 방향이 없으면 직전 방향 반복
```

### 19.4 경고와 실제 공격

빔 방향이 선택되면:

- 경고 영역 표시
- 경고 중 방향 변경 없음
- 실제 빔 피해 영역은 경고 영역과 동일

권장:
- 경고 약 0.75초
- 실제 피해 판정 약 0.60초

---

## 20. 중앙 보안 허브 착지점 범위 폭발

빔이 끝나면 중앙 보안 허브는 **빔 종료 후의 플레이어 실제 위치와 이동 상태를 새로 읽는다.**

빔 전에 계산했던 착지 후보를 그대로 쓰지 않는다.

### 20.1 공격 지점 수

중앙 보안 허브가 현재 위치에서 플레이어가 실제로 도달할 수 있다고 판정한 착지 후보 수에 따라 공격 개수가 결정된다.

```text
후보 3개 이상
→ 2곳 공격
→ 최소 1곳은 중앙 보안 허브 범위 폭발 피해 영역 밖에 남김

후보 2개
→ 1곳 공격
→ 나머지 1곳은 범위 폭발 피해 영역 밖에 남김

후보 1개
→ 범위 폭발 사용 안 함
→ 유일한 착지점을 막지 않음
```

### 20.2 공격 실행

2곳을 공격하는 경우:

- 두 위치를 동시에 경고
- 두 위치를 동시에 폭발

Guard A처럼 순차 폭발하지 않는다.

경고가 시작된 뒤:

- 표적 위치 변경 없음
- 플레이어를 다시 추적하지 않음

권장:
- 경고 약 0.55초
- 실제 피해 판정 약 0.35초

범위 폭발 종료 후 해당 위치에 지속 피해 장판을 남기지 않는다.

## 21. 코어 개방

### 21.1 개방 조건

다음 조건을 모두 만족해야 코어가 열린다.

```text
보호 링크 A 해제
AND
보호 링크 B 해제
AND
중앙 보안 허브의 현재 빔/범위 폭발 공격 단계 종료
```

### 21.2 코어 개방 중 중앙 보안 허브 상태

코어가 열린 동안:

- 빔 사용 안 함
- 범위 폭발 사용 안 함
- 중앙 보안 허브 이동 없음
- 코어 공격 판정에 Rope Impact 가능

권장 개방 시간: **약 2.2초**

### 21.3 한 개방창에서 여러 번 공격

코어가 열린 뒤 첫 Rope Impact가 들어와도 코어를 즉시 닫지 않는다.

개방 시간이 남아 있으면 추가 Rope Impact가 가능하다.

단, 같은 충돌을 여러 프레임 유지한다고 여러 번 피해가 들어가면 안 된다.

추가 피해를 주려면:

```text
첫 Rope Impact
→ 플레이어와 코어 충돌 분리
→ Rope 이동으로 다시 속도 생성
→ 코어에 새로 진입
→ 두 번째 Rope Impact
```

이 과정을 거쳐야 한다.

### 21.4 코어를 못 때렸을 때

개방 시간 동안 코어를 한 번도 못 때려도:

- 추가 즉사 공격 없음
- 중앙 보안 허브 HP 회복 없음
- Guard 재생성 없음

단순히:

```text
코어 닫힘
→ 다음 빔 공격 시작
```

## 22. 좌·우 최종 공격 발판

P3의 왼쪽/오른쪽 최종 공격 발판은 별도 버튼이나 상호작용 장치가 아니다.

두 위치 모두 같은 기능을 가진다.

실제 역할:

- 플레이어가 Rope를 걸 수 있는 기존 Rope 연결 지점 또는 발판 제공
- 중앙 보안 허브 코어까지 Rope Impact 속도를 만들 수 있는 거리 제공
- 코어를 향해 충돌 각도를 만들 수 있는 위치 제공

다음 기능은 없다.

- 해당 위치에서 상호작용 버튼 누르기
- 해당 위치에 서면 코어 무적 해제
- 자동 발사
- 자동 조준
- 한쪽만 정답 처리

플레이어는 왼쪽 또는 오른쪽 중 현재 위치에서 유리한 쪽을 선택한다.

---

## 23. 중앙 보안 허브 공격에 플레이어가 맞았을 때

빔 또는 범위 폭발에 맞으면:

1. 플레이어 HP 감소
2. 피격 시각·음향 효과(VFX/SFX) 발생
3. 공격 중심 또는 공격 진행 방향에서 멀어지는 방향으로 짧게 밀림

밀려남 수치는 다음 조건을 만족하도록 조정한다.

- 맞았다는 위치 변화가 보일 것
- 한 번 맞았다는 이유만으로 자동으로 다른 빔/범위 폭발 판정 안으로 던져 넣지 않을 것
- Rope 이동을 완전히 장시간 상실시키지 않을 것

정확한 거리/시간은 개발자 조정값이다.

## 24. 중앙 보안 허브 파괴와 승리

중앙 보안 허브 HP가 0이 되는 즉시:

- 코어 파손 상태로 전환
- 실행 중 빔 피해 판정 제거
- 실행 중 범위 폭발 피해 판정 제거
- 남아 있는 공격 경고 제거
- 이후 빔/범위 폭발 생성 금지
- 보호막 표시 끄기
- 중앙 보안 허브 경고등 끄기
- 중앙 보안 허브 주변에 국소 스파크/손상 효과
- 중앙 보안 허브 시설 본체는 맵에 남김
- 보호 게이트 잠금 해제
- 보호 게이트 자동 개방

Guard처럼 중앙 보안 허브 전체를 폭발시켜 삭제하지 않는다.

### 24.1 승리 연출 중 플레이어 조작

최종 Rope Impact 직후 매우 짧은 슬로모션을 사용할 수 있다.

권장: 약 0.2초

이 연출 뒤에는 별도 컷신 상태로 플레이어 입력을 길게 잠그지 않는다.

실제 흐름:

```text
최종 Rope Impact
→ 약 0.2초 슬로모션
→ 코어 파손
→ 공격 정지
→ 보호 게이트 자동 개방
→ 플레이어가 직접 보호 게이트 방향으로 이동
```

Sector05의 조직명, 하층 대피 중단의 책임 주체, 보호 우선순위 결정 원인은 Boss04에서 설명하지 않는다.

## 27. 맵과 Rope 이동 계약

기존 설계된 맵 이동 연결 구조는 가능한 한 유지한다.

현재 설계 기준:

- 계획 공간 약 5400×2500
- 기본 Rope 유효 연결 거리 400px
- 필수 설계 이동 연결 21개
- 필수 설계 이동 연결의 최대 거리 353.55px
- 400px 이내 비의도 비인접 구간 지름길 0개

이 값의 의미:

- 필수 이동 연결은 기본 Rope 400px 거리 기준 안에 있다.
- 의도하지 않은 인접 구역 건너뛰기 연결은 확인되지 않았다.
- Boss04 전투 로직을 바꾼다는 이유만으로 맵 전체를 다시 배치하지 않는다.

런타임 구현 뒤 실제 플레이에서 다음 문제가 확인될 때만 해당 구간을 최소 수정한다.

- Guard가 지형에 영구적으로 걸려 추격 불가
- 빔 안전 경로가 실제 플레이어 이동으로 성립하지 않음
- 범위 폭발이 모든 실제 착지점을 동시에 막음
- 최종 공격 발판에서 코어까지 Rope Impact 속도를 만들 수 없음
