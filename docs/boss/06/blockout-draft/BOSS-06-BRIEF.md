# 보스 06 — CONTINUITY WARDEN

> 상태: **구현 전 최종 설계 점검 단계 / 런타임 미구현**
> 위치: **6-8 「ROOFTOP PAD 03」 이후 최종 보스전**
> 전투 공간: **PAD 03 SECURITY COURT**
> 최종 목표: **Warden 돌파 → 출발 게이트 개방 → 정비 셔틀 탑승 → 탈출 완료**

---

# 1. 한눈에 보는 핵심

## 이 보스는 무엇인가

**CONTINUITY WARDEN은 탈출을 막는 마지막 인간 보스다.**

사고의 흑막이나 회사의 최고 책임자가 아니다.
이미 결정된 대피 제한과 보안 통제를 Pad 03 현장에서 직접 집행하는 사람이다.

핵심 대립은 단순하다.

```text
Warden
= 공간을 통제한다.

Player
= Rope로 통제를 뚫는다.
```

Warden은 Rope를 사용하지 않는다.

대신 다음 수단을 사용한다.

- 방패
- 충격봉
- 짧은 추진 대시
- 긴 돌진
- Pad 03 보안 빔

Player는 다음 행동으로 대응한다.

- Rope로 Warden의 뒤를 잡기
- 돌진을 Rope로 넘기기
- 낮은 빔에서는 위로 이동하기
- 높은 빔에서는 아래로 내려오기
- 실수로 떨어지면 복구 발판을 이용해 다시 전투장으로 돌아오기

---

# 2. Player가 Warden에게 피해를 주는 방법

이 보스에서 Player의 기본 공격 수단은 **Rope Impact**다.

```text
Anchor에 Rope 연결
→ Swing Drag로 속도 확보
→ Rope를 놓지 않음
→ Warden 몸에 고속 충돌
→ HP 감소
```

현재 Runtime 기준으로 피해가 발생하려면:

- Rope가 붙어 있어야 함
- 충돌속도 `620 이상`
- Player collider와 Warden body ImpactTarget이 실제로 겹쳐야 함

따라서 `방어 뒤로 넘어가서 일반 공격`이 아니라:

```text
GUARD
→ Anchor
→ Rope Swing
→ Warden 후면에 620+ 충돌
→ DAMAGE
```

가 정확한 공략이다.

Warden은 별도 약점이 없고 몸 전체가 피격 대상이다.
단 `GUARD / COUNTER` 정면 Rope Impact만 막힌다.

공격 가능성을 보장하기 위해 U1~U8 높이를 다시 조정했으며, Main의 모든 합법 Warden 위치가 최소 한 Anchor에서 약 `380.43px` 이내에 들어온다.

`GUARD / COUNTER`는 양쪽 후면 공략 공간이 모두 존재하는 `x=1250..3870`에서만 사용할 수 있다.

상세 검증은 [`DAMAGE-LOOP-PREFLIGHT.md`](./DAMAGE-LOOP-PREFLIGHT.md)를 따른다.

# 3. 가장 중요한 구현 원칙

이 부분은 **다른 보스에서 발생했던 문제를 Boss06에서 반복하지 않기 위한 절대 규칙**이다.

## 최우선 1 — 별도 약점을 만들지 않는다

Boss06에는 Warden 몸 안이나 뒤에 별도의 약점 오브젝트를 생성하지 않는다.

```text
보스 피격 대상
= Warden 몸 전체 1개
```

즉:

- 몸 안에 숨는 약점 금지
- 후방 코어 금지
- 별도 약점 원형 판정 금지
- 가짜 약점을 만들어 검증만 통과시키는 방식 금지

`GUARD`와 `COUNTER`는 약점을 열고 닫는 방식이 아니다.

```text
평상시
→ 앞/뒤 모두 피해 가능

GUARD
→ 정면 피해 0
→ 후면 정상 피해

COUNTER
→ 정면 공격을 막고 밀쳐냄
→ 후면 공격은 정상 피해
```

따라서 **약점이 보스 몸 안에 생겨 공격이 안 맞는 문제 자체가 발생하지 않도록 한다.**

---

## 최우선 2 — 전투 바닥은 하나의 평평한 발판으로 만든다

Main Security Runway는 여러 발판을 이어 붙이지 않는다.

```text
Main Runway
= 하나의 긴 평면 충돌 발판
```

이유:

- 충격봉 공격 중 턱에 걸리지 않음
- 지상 대시가 발판 경계에 막히지 않음
- 긴 돌진이 중간 단차에서 멈추지 않음
- Player가 평범하게 좌우 이동 가능
- 4인 플레이에서도 공간이 덜 답답함

높이 차이는 **좌우 보조 발판**에서만 만든다.

---

## 최우선 3 — 실제로 잡히는 Rope Anchor만 배치한다

전투장에 보이는 Rope Anchor는 실제 게임에서도 전부 잡혀야 한다.

Boss06에서 Rope로 잡을 수 있는 대상은 정확히 다음만 허용한다.

```text
상부 Anchor
U1 U2 U3 U4 U5 U6 U7 U8

복구 Anchor
RR1 RR3
```

그 외에는 Rope 부착 금지:

- Main Runway
- 보조 발판
- 보안 빔 발사 장치
- 출발 게이트
- 탑승 발판
- Warden 본체

특히 **프리뷰에는 보이지만 실제 게임에서는 잡히지 않는 가짜 Anchor를 만들지 않는다.**

---

## 최우선 4 — Warden이 너무 커져서 공간을 막지 않게 한다

Warden의 실제 충돌 크기는 현재 전투 공간 기준으로 다음 범위를 넘기지 않는다.

```text
최대 충돌 크기
약 96 × 150px
```

방패와 충격봉의 공격 범위는 Warden 몸 크기를 키우는 방식으로 구현하지 않는다.

- Warden 몸 = 실제 이동 충돌
- 방패 = 방어 상태 표현
- 충격봉 = 공격 판정
- 보안 빔 = 위험 영역

으로 분리한다.

또한 Warden은:

```text
발판 역할 안 함
Rope Anchor 역할 안 함
```

Player가 Warden 머리 위에 올라서거나 Warden에게 Rope를 거는 상황을 만들지 않는다.

# 4. 구현 우선순위

## 최우선

먼저 이것들이 정상 작동해야 한다.

### 1. Warden 몸 피격

- Warden 몸 전체에 공격 가능
- `GUARD` 정면만 차단
- 후면 공격 가능
- `COUNTER` 정면 공격만 반격
- 별도 약점 없음

### 2. 기본 이동 공간

- Main Runway 하나의 평면 발판
- Player 좌우 이동 가능
- Warden 좌우 이동 가능
- 긴 돌진이 처음부터 끝까지 막히지 않음

### 3. Rope Anchor

- U1~U8 실제 부착 가능
- RR1/RR3 실제 부착 가능
- 의도하지 않은 발판이나 장치에는 Rope가 붙지 않음

### 4. 기본 인간전

- 충격봉 3연타
- 후방 휘두르기
- 지상 추진 대시
- 대각선 추진 대시
- 긴 돌진
- 방어
- 방패 반격

### 5. 복구 구조

- 왼쪽 추락 → R1
- 오른쪽 추락 → R3
- R1/R3에서 Rope를 이용해 Main으로 복귀
- R1/R3까지 놓친 경우에만 런타임 자동 복구 사용

---

## 중요

기본 전투가 정상 작동한 뒤 추가한다.

### 6. 보안 빔

- 낮은 빔
- 높은 빔
- 낮음 → 높음
- 높음 → 낮음
- 후반 최대 3연속

### 7. 행동 연결

예:

```text
보안 빔 종료
→ 추진 대시
→ 충격봉 공격
```

또는

```text
추진 대시
→ 방어
```

### 8. 전투 강도 변화

화면에 Phase는 표시하지 않는다.

체력이 낮아질수록:

- 보안 빔 사용 증가
- 2단 연결 증가
- 제한적 3단 연결 등장
- 방어 사용 감소
- 반격 사용 증가
- 긴 돌진 후 빈틈은 조금 짧아짐

새 기술은 추가하지 않는다.

---

## 후순위

전투가 완전히 정상 작동한 뒤 다듬는다.

- 정확한 체력
- 공격 피해량
- 공격 속도
- 대시 속도
- 빔 지속시간
- 시각 효과
- 효과음
- 대사 세부 표현
- 카메라 연출 미세 조정

# 5. 전투 공간 구조

전체 구조는 다음과 같다.

```text
                    열린 하늘

       U1 — U2 — U3 — U4 — U5 — U6 — U7 — U8
                  상부 Rope 이동선


              [보조 발판 L]   [보조 발판 R]


진입 ===================================== 출발 게이트
              MAIN SECURITY RUNWAY
                       WARDEN


      [R1 복구]                         [R3 복구]
```

중앙 Main Runway는 끊지 않는다.

전투 중 가장 중요한 공간은 Main Runway다.

여기서:

- 충격봉
- 방어
- 반격
- 지상 대시
- 긴 돌진

이 모두 이루어진다.

---

# 6. 상부 Rope Anchor

U1~U8은 Player가 Warden의 통제를 우회하기 위한 핵심 이동선이다.

주요 용도:

- 방어 중인 Warden의 뒤로 넘어가기
- 긴 돌진 피하기
- 낮은 보안 빔 피하기
- Warden의 정면 압박에서 탈출하기

Warden은 이 Anchor를 사용하지 않는다.

Player가 상부에 오래 머물면 Warden이 직접 따라가는 대신 **높은 보안 빔**을 호출한다.

---

# 7. 보조 발판

좌우에 작은 발판을 하나씩 둔다.

목적:

```text
Main
→ 대각선 추진 대시
→ 보조 발판
→ 다시 Main
```

보조 발판은 제2의 전투장이 아니다.

Warden이 잠깐 위치를 바꾸는 공간이다.

Player와 Warden이 올라갔을 때 서로 완전히 막히지 않을 정도의 폭을 확보한다.

---

# 8. 복구 공간

## R1

왼쪽 외곽에서 떨어졌을 때 받는 복구 발판.

`RR1` Anchor를 이용해 Main으로 돌아온다.

## R3

오른쪽 외곽에서 떨어졌을 때 받는 복구 발판.

`RR3` Anchor를 이용해 Main으로 돌아온다.

## 더 아래로 떨어졌을 때

R1/R3까지 완전히 놓친 경우에만 런타임 자동 복구를 사용한다.

중앙 바닥 아래에 큰 숨은 복구 발판을 만들지 않는다.

즉:

```text
일반 실수
→ R1/R3
→ Rope 복귀

큰 추락
→ 자동 복구
```

로 단순화한다.

---

# 9. 직접 공격

## 충격봉 3연타

```text
1타
→ 2타
→ 강한 내려찍기
```

Player가 멀어지면 공격을 끝까지 허공에 휘두르지 않고 중간에 취소한다.

---

## 후방 휘두르기

Player가 Rope로 뒤를 잡았을 때 사용하는 느린 대응 공격.

- 예고가 분명해야 함
- 바로 추가 공격으로 이어지지 않음
- Player가 뒤를 잡은 보상은 유지

---

## 지상 추진 대시

짧게 전진한다.

- 이동 자체에 접촉 피해 있음
- 이후 충격봉 또는 방어로 연결 가능

---

## 대각선 추진 대시

Main과 보조 발판 사이를 이동한다.

Warden이 높은 Rope Anchor까지 따라가지는 않는다.

---

## 긴 돌진

대표적인 큰 공격이다.

```text
Player 압박
→ 돌진 예고
→ 방향 고정
→ 긴 돌진
→ Player 회피
→ Warden 큰 빈틈
→ Player 반격
```

후반에도 이 공략법은 바뀌지 않는다.

다만 후반에는 반격할 수 있는 시간이 조금 줄어든다.

---

# 10. 방어와 반격

## 방어

방패를 들고 있는 동안:

- 정면 공격 = 피해 없음
- 후면 공격 = 정상 피해

Player는 Rope로 Warden의 뒤를 잡는 것이 기본 해법이다.

---

## 방패 반격

Warden이 명확한 반격 자세를 취한다.

Player가 정면에서 공격하면:

```text
방패로 막음
→ Player 밀어냄
→ 거리 초기화
```

Player가 공격하지 않으면 반격 자세는 자동으로 끝난다.

---

# 11. 보안 빔

Warden은 Pad 03에 설치된 고정 보안 장치를 사용한다.

발사 장치 자체는 벽이나 발판이 아니다.

Player 이동을 물리적으로 막지 않고, 빔이 지나가는 영역에만 피해를 준다.

## 낮은 빔

Main Runway를 위험하게 만든다.

Player 대응:

```text
Main
→ Rope
→ 상부 Anchor
```

---

## 높은 빔

상부 Rope 이동 공간을 위험하게 만든다.

Player 대응:

```text
Rope 해제
→ Main 착지
```

---

## 연속 빔

기본:

```text
낮음
높음
낮음 → 높음
높음 → 낮음
```

후반:

```text
낮음 → 높음 → 낮음
높음 → 낮음 → 높음
```

연속 순서는 **공격 시작 전에 모두 보여준다.**

어려운 이유가 “몰라서 맞는 것”이 아니라 “알지만 정확히 움직여야 해서 어려운 것”이어야 한다.

---

# 12. 보안 빔 사용 중 Warden

빔이 실제로 발사되는 동안 Warden은 직접 공격하지 않는다.

```text
보안 빔 사용
→ Warden 천천히 위치 압박
→ 빔 종료
→ 다음 직접 공격
```

따라서:

```text
빔 + 충격봉 + 대시
```

가 동시에 겹치는 상황은 만들지 않는다.

후반의 연계도 반드시 빔 종료 뒤에 시작한다.

---

# 13. 전투 강도

화면상 Phase 구분은 없다.

## 초반

인간전 중심.

- 충격봉
- 대시
- 방어
- 반격
- 긴 돌진

보안 빔은 가끔 사용.

## 중반

- 보안 빔 증가
- 2단 연결 증가

예:

```text
높은 빔 → 대시
낮은 빔 → 긴 돌진
대시 → 충격봉
```

## 후반

- 보안 빔 비중 증가
- 제한적 3단 연결
- 반격 사용 증가
- 방어 사용 감소
- 긴 돌진 후 빈틈 감소
- 최대 3연속 보안 빔

새로운 필살기는 없다.

---

# 14. 첫 등장

Warden은 이미 출발 게이트 앞에 서 있다.

화려하게 뛰어들거나 추진기로 등장하지 않는다.

짧은 대화를 나눈 뒤 전투가 시작된다.

현재 대사 초안:

```text
WARDEN
Maintenance worker.
Your evacuation clearance has been revoked.

PLAYER
I know.

WARDEN
Then leave the pad.

PLAYER
Open the gate.
```

대사는 추후 다듬을 수 있다.

---

# 15. 승리

Warden은 죽지 않는다.

마지막 공격을 받으면:

```text
방패 자세 붕괴
→ 충격봉 떨어짐
→ Warden 쓰러짐
→ 기절
→ 전투 종료
```

그 뒤:

```text
보안 통제 해제
→ 출발 게이트 조명 켜짐
→ 게이트 열림
→ 카메라 오른쪽 이동
→ 정비 셔틀 최초 공개
```

전투 중에는 Shuttle을 보여주지 않는다.

---

# 16. 마지막 이동과 탈출

전투 중에는 Main Runway 오른쪽 끝과 Gate 사이에 약 180px의 추락 구간이 있다.

Boss 승리 후 이 구간에 짧은 연결 발판이 열린다.

```text
전투 중
Main 끝 | 추락 구간 | 잠긴 Gate

승리 후
Main 끝 | 연결 발판 | 열린 Gate | 탑승 발판
```

카메라 연출이 끝난 뒤 Player 조작권을 다시 준다.

Player가 직접:

```text
Gate 통과
→ Shuttle까지 이동
→ 탑승
→ 탈출 완료
```

한다.

# 17. 이 보스에서 절대 하면 안 되는 것

- Warden 몸 안에 약점 생성
- 별도 약점을 공격해야만 피해가 들어가는 구조
- Warden 몸을 거대한 원형 충돌체로 구현
- 방패나 충격봉을 Warden 몸 충돌 크기에 포함
- Main Runway를 여러 높이 발판으로 잘게 나눔
- 보이는 Anchor가 실제로는 잡히지 않음
- 의도하지 않은 발판이나 장치에 Rope가 붙음
- 보안 빔 발사 장치가 Player 이동을 막음
- 빔이 실제 벽처럼 Player를 밀어냄
- Warden이 Rope를 사용함
- Warden 위에 Player가 올라설 수 있음
- 전투 중 Shuttle을 미리 보여줌
- Warden을 처형하거나 사망 확인 연출
- 새로운 흑막이나 CEO를 마지막에 추가

# 18. 구현 완료 전에 반드시 확인할 것

## 피격

- 평상시 앞에서 때리면 피해가 들어가는가
- 뒤에서 때려도 피해가 들어가는가
- 방어 중 앞에서는 막히고 뒤에서는 맞는가
- 반격 자세에서 앞 공격만 반격하는가

## 이동 공간

- Main을 Player가 끝까지 달릴 수 있는가
- Warden도 Main을 끝까지 이동할 수 있는가
- 긴 돌진이 중간 발판이나 턱에 막히지 않는가
- Player 4명과 Warden이 있어도 지나갈 공간이 남는가

## Rope

- U1~U8 전부 실제로 잡히는가
- RR1/RR3가 실제로 잡히는가
- 다른 발판이나 Gate가 Rope 대상으로 잡히지 않는가
- Warden이 Rope 대상으로 잡히지 않는가

## 화면

실제 Gameplay View에서:

- Warden
- Player
- 공격 예고
- 회피할 공간
- 사용할 Anchor

가 동시에 보이는지 확인한다.

특히 `GUARD`, `CHARGE`, `LOW/HIGH 보안 빔`은 반드시 실제 게임 화면에서 검수한다.
