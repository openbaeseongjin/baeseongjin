# SECTOR 01 — STAGE SCALE / UNIQUENESS GATE REV1

> DESIGN LOCKED PROCESS RULE

Every Stage must pass these gates before full-package approval:

1. MAP SCALE / WORLD FOOTPRINT
2. MAP SIMILARITY
3. OBSTACLE FUNCTION
4. STAGE LENGTH / PACING
5. CURRENT GITHUB RUNTIME IMPLEMENTATION

## Bounds derivation order

`CONCEPT → TRAVERSABLE SILHOUETTE → OBSTACLE SIZE → MOVEMENT AXIS → VERIFIED ROPE REACH → RECOVERY → CAMERA → PLAYTIME → WIDTH/HEIGHT`

Do not inherit the previous Stage's width/height without proving why.

## Map similarity

Compare with adjacent and prior maps:
- traversable silhouette
- movement axis
- Anchor arrangement
- landing rhythm
- enclosure width
- failure direction
- enemy/pressure angle
- Key approach
- Augment expression
- topology / architectural causality

0–1 meaningful overlaps: PASS
2: REVIEW
3+: REDESIGN

## Obstacle function

An industrial object is not unique just because its art is different.
Classify its gameplay function:
- AFFORDANCE / USE
- MASS BLOCKING / BYPASS
- FORCE / TRAJECTORY
- TIMING / RHYTHM
- ENEMY / LOS PRESSURE
- ACCESS / OBJECTIVE
- MOVING PLATFORM
- RECOVERY / SAFETY

Adjacent Stages should not repeat the same primary obstacle function.

## Length / pacing

Record:
- physical width / height
- mandatory meaningful decision count
- first-clear target
- mastered-clear target
- retry time for each failure pocket

If added width/height only increases empty travel, REDESIGN.

## Runtime check

Before every Stage draft/package:
- recheck latest `main`
- inspect actual Area Catalog
- inspect Seamless compiler behavior
- inspect current player/Rope constants
- inspect relevant Story/Camera/Audio owners

Do not rely on stale planning constants.

Current verified baseline for this package:
- Rope hook speed 1200
- Hook flight ratio 1/3
- Effective hook reach 400px
- Grapple link budget 600
- Player jump speed 440
