# 5-5 RUNTIME HANDOFF

Implement `priority-route-lock-v1` using the same shared proof-state philosophy as existing Sector access progression.

Locked:
- A1 unavailable as a new Rope candidate
- physical ascent entry blocks progression
- ascent still visible

Unlocked after `priority-directive`:
- A1 becomes attachable
- physical route opens
- no extra inventory key

Key branch:
- Jammer alternates k1-low/k1-high, one at a time
- AEGIS protects the proof terminal
- kill optional

Return uses K3 + return balcony to avoid mandatory full retrace.
