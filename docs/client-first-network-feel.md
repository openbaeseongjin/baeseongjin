# 클라이언트 체감 우선 멀티플레이 개선 계획

## 결론

멀티플레이의 자기 캐릭터는 서버 응답을 기다리지 않고 로컬 입력으로 현재 시간축을 계속 시뮬레이션한다. 일상적인 권위 스냅샷은 소유 플레이어의 위치·속도·로프를 복원하지 않으며, 클라이언트 운동 상태를 서버가 허용 tick·속도·거리 봉투 안에서 받아 공용 월드에 반영한다. 동료와 적은 별도의 지연된 시간축에서 두 권위 스냅샷 사이를 보간한다.

이는 최종 상태를 클라이언트에 맡긴다는 뜻이 아니다. 이동·점프·정적 지형 충돌·로프·자기 탄환과 자신에게 닿는 적 탄환의 피격·로프 절단 연출은 먼저 예측하지만, HP·적 사망·최종 로프 상태·플레이어 사망과 체크포인트 부활·아티팩트는 서버가 검증하고 확정한다.

## 필수 이벤트 계약

플레이어·로프처럼 특정 당사자가 있는 게임플레이 이벤트의 최초 트리거는 소유자 또는 피해 클라이언트다. 클라이언트는 서버 왕복 전에 해당 사건의 운동·UI·연출 반응을 시작하고 claim을 전송한다. 서버는 claim을 검증하고 중복을 제거해 최종 상태를 확정·배포하지만, 모바일 체감 경로에서 사건을 먼저 시작하지 않는다. 몹·적 투사체 생성과 궤적처럼 어느 플레이어에게도 귀속할 수 없는 중립 월드 사건은 서버가 진행한다.

- 자기 행동: 소유 클라이언트가 트리거한다.
- 피격·충돌·로프 절단: 피해 클라이언트가 트리거한다.
- 중립 월드 사건: 서버가 생성과 시뮬레이션을 담당하며 특정 대표 클라이언트에게 위임하지 않는다.
- 여러 클라이언트가 감지할 수 있는 사건: 같은 결정적 event key를 사용하고 서버가 한 번만 승인한다.
- 세션 연결·퇴장·빈 방 제거·서버 장애는 서버 시작을 허용하는 예외다.

## 기존 구현 전환 상태

현재 자기 이동·로프·자기 공격 충돌·자기 피격·로프 절단·낙사와 사망 시 개인 체크포인트 부활은 클라이언트 선행 경로가 구현돼 있다. 적 발사 생성과 적 투사체 궤적은 서버 중립 시뮬레이션으로 확정했다. 체크포인트 도달과 보상 시작, 정상 도달은 플레이어 당사자 사건과 중립 월드 사건의 경계를 먼저 정합성 검토해야 한다. 플레이어 당사자 사건을 수정하거나 확장할 때 서버 시작형 경로를 복제하지 말고 담당 클라이언트 claim과 멱등 event key를 먼저 설계한다.

## 레퍼런스에서 채택할 원칙

- [Valve Source Multiplayer Networking](https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking): 자기 입력은 클라이언트 예측, 다른 엔티티는 과거 시간축의 두 스냅샷 사이 보간을 사용한다.
- [Unity Netcode prediction](https://docs.unity.cn/Packages/com.unity.netcode@1.5/manual/intro-to-prediction.html): owner-predicted 객체는 입력 프레임에 반응하고, 권위 스냅샷 수신 후 롤백·재실행한다.
- [Unity Netcode interpolation](https://docs.unity.cn/Packages/com.unity.netcode@1.5/manual/interpolation.html): 외삽은 보간 표본이 없을 때만 쓰는 제한적 폴백이며 예측과 다른 시간축이다.
- [Unreal networked movement](https://dev.epicgames.com/documentation/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine): 클라이언트 이동 기록과 서버 보정을 별도 예측 데이터로 관리한다.

## 현재 어긋남

1. `MultiplayerGameApp.update()`는 명령 전송 시점에만 예측을 갱신해 자기 캐릭터가 렌더 프레임마다 계속 진행되지 않는다.
2. 초기 예측기는 최신 스냅샷부터 미승인 명령까지만 재생하며 현재 예측 틱과 잔여 프레임 시간을 소유하지 않았다.
3. 새 권위 상태를 물리·표시 상태 구분 없이 바로 복원해 작은 오차도 화면 순간이동이 된다.
4. `RemoteWorldStateBuffer`는 두 스냅샷 사이 보간이 아니라 최신 위치에서 속도로 미래를 외삽한다.
5. 자기 탄환은 서버 `spawn` 사건이 도착한 뒤에만 표시된다.

## 순차 구현 단위

### A. 지속되는 소유자 예측 시계

- [완료] `OwnerPredictionRuntime`이 현재 predicted tick과 최대 512틱 입력 이력을 소유한다.
- [완료] 앱의 기존 120Hz 고정 스텝마다 예측을 진행하고 명령 전송 cadence는 별도 60Hz로 제한한다.
- [완료] 정상 submit과 승인 receipt는 소유자 예측을 되감지 않고, 상태 전송 거부 receipt만 마지막 공유 상태에서 현재 predicted tick까지 입력을 재실행한다.

### B. 롤백·재실행과 표시 보정

- [완료] 정상 승인 중 플레이어·로프는 소유 클라이언트가 수렴 원점이며, 서버와 동료가 검증된 `owner-motion` 상태를 따라간다.
- [완료] `owner-motion` receipt를 검증·중복 제거하고, 거부 때만 마지막 공유 상태에서 미확정 입력을 현재 predicted tick까지 재실행한다.
- [완료] 거부 복구의 160px 이하 위치 오차는 별도 표시 offset으로 100ms 안에 감쇠한다.
- [완료] 거부 복구의 160px 초과 오차와 생명 상태 변경, 확정 부활은 즉시 공유 상태로 맞춘다.
- [완료] 최근 보정 거리·남은 보정 시간·하드 스냅 누계를 예측기 지표로 제공한다.

### C. 실제 원격 스냅샷 보간

- [완료] 최대 8개 스냅샷을 보관하고 100ms 지연된 서버 tick의 앞뒤 표본을 보간한다.
- [완료] 정상 수신 중에는 외삽하지 않고, 미래 표본이 없을 때만 최대 120ms 외삽한다.
- [완료] 자기 플레이어는 소유자 예측 위치를 사용하고 HP·체크포인트 부활·로프 절단 같은 비위치 판정은 최신 권위 값을 즉시 사용한다.

### D. 자기 공격 예측

- [완료] 자기 자동 발사에 소유자와 발생 tick 기반 `predictionId`를 붙여 탄환과 예상 타격 VFX를 즉시 표시한다.
- [완료] 서버 `spawn/resolve`가 같은 ID를 확정하면 중복 생성·VFX 없이 승격한다.
- [완료] 로컬 충돌은 `predictionId`·대상·clientTick·적중 위치만 hit claim으로 보내고, 서버가 연결 소유권·탄환·대상·tick 범위·위치 오차·중복을 검증한 뒤 서버 대미지로 확정한다.
- 적 HP와 사망은 권위 스냅샷을 따른다. 자신과 교차한 적 탄환은 로컬 예측 위치의 몸체와 로프를 먼저 판정해 즉시 피드백·넉백·로프 해제를 적용하고, `projectileId`·clientTick·종류·위치 claim을 서버에 보낸다. 서버가 궤적과 피해 플레이어의 연결 소유권을 검증해 HP와 최종 상태를 확정한다.
- 로프 부착 여부가 서버와 잠시 다르다는 이유만으로 소유 플레이어 표시 위치를 하드 스냅하지 않는다. 생명 상태 전환과 큰 위치 오차만 하드 스냅 대상으로 둔다.
- 자신에게 닿은 적 탄환은 클라이언트가 먼저 `impact-claim`을 보내고 즉시 적용한 넉백·로프 해제 상태를 같은 틱의 `owner-motion`으로 이어 보낸다. 서버가 이후 스냅샷으로 이 운동 결과를 되감지 않는다.

### E. 계측과 실제 기기 검증

- [완료] Issue #181의 RTT·스냅샷 간격·대기 명령·거부율을 새 구조 위에 재적용한다.
- [완료] 보정 거리 p50/p95, 하드 스냅 수, 외삽 시간과 예측 취소 수를 `?metrics=1` 패널에 추가한다.
- [완료] 0/50/100/200ms 왕복 지연과 0/2/5% 송신 명령 손실을 한 멀티 E2E에서 검증하고 전체 테스트를 3분 이내로 유지한다.
- [완료] 손실된 명령의 RTT 추적 기록을 권위 ACK로 정리하고 최근 2,048개 상한을 두어 장시간 세션의 계측 메모리를 제한한다.
- [완료] 실제 2인 WebSocket에서 이동 뒤 중립 입력을 유지해 소유자·서버·동료의 위치 4px, 속도 20px/s 이내와 로프 상태 일치를 검증한다.
- [완료] 새 스냅샷마다 추정 서버 시계를 제한 보정하고 장시간 수신 시계 드리프트가 지속 외삽으로 누적되지 않는지 검증한다.

## 실행 순서

A → B → C → D → E로 진행한다. A와 B가 자기 조작감의 직접 원인이므로 먼저 별도 GitHub 작업으로 완료하고 PC·모바일 체감을 확인한 뒤 공격 예측 범위를 넓힌다. 각 단위는 Issue, 단일 Lore 커밋, PR, 일반 merge commit으로 `main`에 반영한다.
