# 기획 결정 요청·답변 추적

이 문서는 개발 구현이 준비되어 있고 **기획 결정만 기다리는 항목**을 우선순위 순으로 정리하고, 기획자가 같은 문서에 답변을 남길 수 있게 한다. 개발자는 답변이 붙은 항목부터 구현을 시작한다.

- 상태 범례: `요청됨` → `답변됨` → `구현 완료`, 또는 `보류`
- 마지막 갱신: 2026-08-16

## 현재 구현 기준

| 축 | 상태 |
| --- | --- |
| 월드 | `1-1 → 3-8` 24개 영역 `MOCK INTEGRATED`, 4-1~4-8 standalone `GRAYBOX READY` |
| 시스템 | 로프 코어·전투(Sentry/Patrol Drone)·Foundation 3종·Wind·Access Scan Field·Cutter Fire·2인 멀티 완료 |
| 프레젠테이션 | 아트·오디오는 mock 교체 대기. Sector 01~04 Camera·Story의 현재 인계 범위는 코드 반영 완료 |
| 검증 | 실제 브라우저·기기 플레이테스트 0건 (`PLAYTEST VERIFIED` 없음) |

정확한 Stage별 상태는 [`scenario-development-integration.md`](./scenario-development-integration.md)를 따른다.

## 응답 방법

1. 각 항목의 **기획자 답변** 란에 직접 작성하고 상태를 `답변됨`으로 바꾼다.
2. 부분 답변도 허용한다. 확정된 부분만 먼저 쓰고 나머지 결정 항목은 `보류`로 남긴다.
3. 답변은 구현 가능한 계약(이름·수치·흐름·트리거·UI) 형태가 가장 좋다. 아이디어 목록은 답변으로 처리하지 않는다.
4. 답변 커밋이 병합되면 개발자가 해당 항목 구현에 착수한다.

## P1. Specialization 성장 규칙 (2-3)

- **상태**: `요청됨`
- **블로킹 이유**: 로그라이크의 핵심인 성장 루프가 현재 1-4 Foundation 1회 선택에서 정지한다. 2-3의 Specialization이 placeholder로만 열려 있어 성장 곡선과 밸런스를 만들고 검증할 수 없다.
- **현재 구현**: 2-3 진행은 `interact` placeholder로 열림. 선택 UI·입력·개인별 멀티는 1-4 Foundation 선택 primitive를 재사용 가능. Foundation과 Specialization의 ID·의미 체계는 합치지 않는다.

### 결정 필요 항목

- [ ] Specialization 종류(3종 이상)별 이름과 성장 방향 — 1-4 Foundation(Impulse Coil/Relay Link/Shear Current)과의 관계 유지 여부
- [ ] 각 효과의 상세 동작과 수치
- [ ] 선택 방식: 1개 고정? 재선택 가능? 선택 pool 구성?
- [ ] 획득·손실 규칙: 사망·체크포인트 부활 시 유지 여부, 런 종료 시 초기화
- [ ] 선택 화면 UI 문구와 진행 cue

- **상태**: `요청됨`

## 참고: 기획 입력 없이 개발이 진행 가능한 항목

개발 쪽에서 계약 없이 계속 진행할 수 있는 작업이다. 필요한 경우 알려주면 바로 착수한다.

- 4-5~4-8 authored catalog (4-4 이후 전환·보스 미정이라 content-boundary 유지)
- Sector 01·02 Camera Zone·Story 인계 문서 코드 반영 (`bsh/scenario/1/CAMERA-STORY-IMPLEMENTATION-HANDOFF.md`, `bsh/scenario/2/STORY-IMPLEMENTATION-HANDOFF.md`)
- 정식 아트·오디오의 mock 교체 (각 asset 가이드와 교환 형식으로 인계)
- 두 기기 플레이테스트 (P1~P3 수치가 확정되는 시점에 일정 조율 권장)
