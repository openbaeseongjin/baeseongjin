# 픽셀 그래픽 디자인 규격

이 문서는 정식 캐릭터, 오브젝트, 배경과 이펙트를 제작할 때 사용하는 픽셀 그래픽의 시각 규격이다. 산나비에서 보이는 작은 캐릭터와 거대한 사이버펑크 배경의 대비, 플레이 영역의 높은 가독성, 원경으로 갈수록 낮아지는 도트 밀도를 참고한다. 구체적인 캐릭터 디자인, 건물 형태, 문양과 연출을 복제하지 않고 이 프로젝트의 폐쇄형 수직 기업도시에 맞는 독자적인 결과물을 만든다.

## 적용 범위와 우선순위

- 이 문서는 제작 캔버스, 시각적 크기, 타일 격자와 화면 위계를 정한다.
- 그래픽 작업 위치와 인계 항목은 [`graphics-asset-guide.md`](./graphics-asset-guide.md), 캐릭터와 환경의 런타임 형식은 각각 [`sprite-asset-format.md`](./sprite-asset-format.md)와 [`environment-asset-format.md`](./environment-asset-format.md)를 따른다.
- 아래 크기는 한 프레임 또는 한 타일의 제작 캔버스 기준이다. 실제 불투명 픽셀 영역은 여백, 동작과 실루엣에 따라 더 작을 수 있다.
- 제작 캔버스와 게임 출력 크기는 정수 배율을 우선하고 픽셀 경계를 맞춘다. 비정수 확대·축소, 안티앨리어싱과 흐린 보간으로 규격을 맞추지 않는다.
- 캔버스 크기와 충돌체는 별도 계약이다. 그래픽 크기로 collider, hitbox, 피해량, 물리나 네트워크 권위를 결정하지 않는다.
- 현재 `24×24` player mock과 production starter는 렌더러·manifest 연결을 검증하는 개발 자료이며 정식 캐릭터 디자인의 크기 기준이 아니다. 정식 player atlas는 이 문서의 `32×32`~`48×48` 범위에서 실제 셀 크기를 정하고 manifest의 `frameSize`에 기록한다.

기본 모듈은 `32×32` 타일이다. 지형과 근경은 이 격자에 맞추고, `16px` 단위 오브젝트는 반 타일, `8px` 두께는 4분의 1타일로 정렬한다.

## 생명체와 캐릭터

| 종류 | 기본 제작 캔버스 | 적용 기준 |
| --- | --- | --- |
| 주인공·인간형 NPC | `32×32`~`48×48` | 눈·코·입은 점 단위로 단순화하고 실루엣과 자세를 먼저 읽히게 한다. |
| 주인공 액션 확장 | `48×48`~`64×64` | 사슬 낫, 긴 팔 동작과 잔상처럼 몸 밖으로 뻗는 프레임에 사용한다. 몸 중심의 시각 크기는 기본 상태와 일치시킨다. |
| 소형 드론·경비 로봇 | `24×24`~`32×32` | 주인공과 같거나 약간 작게 보이게 하고 공격 예고와 이동 방향을 형태로 구분한다. |
| 대형 몹·보스 | `64×64`~`128×128` 이상 | 일반 캐릭터보다 화면 점유 면적이 최소 네 배 이상 커 보이게 해 위압감을 만든다. 여러 타일에 걸치는 실루엣을 허용한다. |

플레이어와 NPC는 실제 게임 출력 크기에서 얼굴의 세부 묘사보다 머리, 몸통, 장비와 동작 방향의 구분을 우선한다. `idle`, `run`, `jump`, `fall`, `rope`, `hit`, `respawn`처럼 플레이 중 구분해야 하는 상태는 첫 프레임의 자세만으로도 식별할 수 있어야 한다.

## 플레이어 상호작용 장애물

| 종류 | 제작 캔버스 | 적용 기준 |
| --- | --- | --- |
| 기본 바닥·벽 플랫폼 | `32×32` | 캐릭터가 안정적으로 딛거나 벽을 탈 수 있는 기본 타일이다. 연결면과 모서리가 반복 배치에서 끊기지 않아야 한다. |
| 얇은 난간·철판 발판 | `32×8` 또는 `32×16` | 아래에서 위로 통과할 수 있는 one-way 표면과 고체 발판을 실루엣으로 구분한다. |
| 즉사 가시·소형 트랩 | `16×16` 또는 `32×16` | 한 줄로 이어 붙여도 위험 방향과 빈틈이 명확해야 한다. |
| 이동·회전 트랩 | `32×32`~`64×64` | 회전 범위와 위험 반경을 정지 화면에서도 예측할 수 있게 한다. |
| 회전 톱날 | `48×48` 또는 `64×64` | 원형 실루엣과 중심축을 분명히 하고 회전 잔상이 충돌 경계를 가리지 않게 한다. |
| 레이저 장치 | 발사기 `32×32`, 빔 반복 타일 `16×32` | 발사기, 예고, 활성 빔을 서로 다른 형태와 명도로 구분한다. |
| 와이어 스윙 앵커 | `16×16`~`32×32` | 캐릭터보다 작거나 같은 크기로 유지하되 배경 장식과 혼동되지 않는 고유 외곽선을 사용한다. |
| 파괴 가능한 벽·기믹 문 | `32×64`~`64×64` | 파괴 전·후 또는 잠금·해제 상태가 균열, 구조와 움직임으로 구분돼야 한다. |

이 표는 시각 제작 기준이다. 실제 collision surface와 one-way edge는 기존 게임 geometry를 유지하며 PNG 외곽선으로 새 충돌을 만들지 않는다.

## 배경 레이어

| 깊이 | 제작 크기 | 적용 기준 |
| --- | --- | --- |
| 근경 벽면·연구실 wall | `32×32`~`64×64` 타일 | 플랫폼의 `32×32` 격자와 정확히 맞추고 충돌 지형으로 오해할 장식을 이동 경로에 두지 않는다. |
| 중경 빌딩·네온 간판·파이프 | `128×128`~`256×256` 컴포넌트 | 큰 구조를 묶음으로 제작해 맵에서 반복 배치하고 반복 경계와 시차 기준선을 기록한다. |
| 원경 하늘·달·거대 실루엣 도시 | `512×288` 또는 `960×540` | 16:9 통이미지 또는 대형 타일셋으로 제작하고 근경보다 도트 밀도, 명도 대비와 채도를 낮춘다. |

배경은 far·mid·near 순으로 도트 밀도와 대비를 낮춘다. 큰 실루엣과 제한된 인공 조명으로 공간 규모를 만들고, 세부 픽셀을 늘려 플레이 영역과 경쟁시키지 않는다.

## 장식물과 이펙트

| 종류 | 제작 캔버스 | 적용 기준 |
| --- | --- | --- |
| 쓰레기통·상자·가로등 | `16×16` 또는 `16×32` | 이동 경로에서 발판이나 위험물로 오해되지 않게 한다. |
| 가게 간판·모니터 | `32×32` 또는 `32×64` | 배경 정보로 읽히되 상호작용 오브젝트보다 낮은 대비를 사용한다. |
| 연구실 캡슐·대형 기계 | `64×64` 이상 | 여러 타일에 걸쳐 배치할 수 있으며 실제 충돌 여부를 작업 README에 별도로 기록한다. |
| 사슬 낫 궤적·타격·폭발 | 프레임당 `32×32`~`64×64` | 판정 순간과 방향을 선명하게 전달하되 플레이어, 앵커와 지형 경계를 오래 가리지 않는다. |

VFX의 캔버스 확장은 판정 크기 확장이 아니다. 발사체 본체, 공격 예고, 충돌 효과와 잔상은 가능하면 별도 리소스로 나눠 수명과 가독성을 독립 조절한다.

## 화면 위계와 색 사용

- 플레이어, 로프 앵커, 충돌 플랫폼, 위험물과 즉시 상호작용 오브젝트는 밝기·윤곽·동작 대비를 높인다.
- 근경에서 원경으로 갈수록 명도 대비와 채도를 낮춰 플레이 영역을 앞으로 분리한다.
- 상태 차이를 색 하나로만 표현하지 않는다. 자세, 외곽선, 점멸 리듬, 방향과 크기 변화 중 하나 이상을 함께 사용한다.
- 작은 캐릭터와 거대한 배경 컴포넌트의 크기 대비로 고밀도 사이버펑크 화면을 만든다. 캐릭터 해상도를 불필요하게 키워 배경의 규모감을 줄이지 않는다.
- 장식용 아이콘과 이모지는 규격 문서와 자산에 관성적으로 추가하지 않는다. UI 아이콘은 실제 조작·상태 의미가 있을 때만 `ui` 자산으로 제작한다.

## 제작과 인계 체크리스트

- 자산 README에 제작 캔버스, 실제 불투명 영역, 의도한 게임 출력 크기와 기준 격자를 기록한다.
- 액션 확장 프레임을 사용하면 기본 몸체와 anchor가 프레임 사이에서 흔들리지 않는지 확인한다.
- 타일과 반복 컴포넌트는 좌우·상하 이음새와 맵 격자 정렬을 확인한다.
- 데스크톱과 모바일 실제 게임 크기에서 캐릭터, 위험물, 앵커와 통과 가능한 발판을 배경과 즉시 구분할 수 있는지 확인한다.
- 원본, 투명 PNG export, atlas·프레임 미리보기, 사용 도구·버전, 외부 자료의 출처와 라이선스를 함께 인계한다.
- 담당 개발자는 정규화한 runtime package에 실제 셀과 atlas 크기를 기록하고 자산 종류별 validator를 통과시킨다.
