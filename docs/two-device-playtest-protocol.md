# 두 기기 협동 플레이테스트 절차

이 문서는 자동 테스트로 대신할 수 없는 로프 조작감과 협동 플레이 체감을 서로 다른 실제 기기 두 대에서 한 세션으로 검증하기 위한 기준이다. 문서를 작성한 것과 실제 플레이테스트를 통과한 것은 구분한다.

## 준비

- 두 기기에서 배포 페이지를 연 뒤 설정 버튼을 1초 길게 눌러 디버그 패널의 **디버그 수치 표시**를 켠다.
- 양쪽 화면의 버전이 같고 최신 배포 버전인지 확인한다.
- 한 명이 4자리 채널을 만들고 다른 한 명이 같은 채널에 참가한다.
- 플레이어 A에게는 조작법을 설명하지 않는다. 플레이어 B는 진행 순서와 기록을 담당한다.
- 시작 전에 아래 기록표에 기기, 브라우저, 접속망, 빌드 버전, 채널 번호와 월드 시드를 적는다.

권장 세션 길이는 15~20분이다. 정상까지 도달하지 못해도 실패 지점과 월드 시드를 남기면 유효한 결과다.

## 메인 시나리오

1. **설명 없는 로프 학습**
   - 플레이어 A가 처음 부착, 스윙, 해제를 성공한 시간을 각각 기록한다.
   - 시작 후 1~2분 안에 로프를 타는 재미와 다음 이동 방향을 이해했는지 짧게 묻는다.
2. **등반과 첫 generic Augment 선택**
   - 1-4 Maintenance Node까지 함께 등반하며 처치, 피해, 로프 절단과 첫 Augment 선택 시간을 기록한다.
   - 플레이어 A는 보상 선택 화면에서 잠시 선택을 미룬다.
   - 이때 월드 시간, 적, 투사체와 플레이어 B의 조작이 계속 진행되는지 확인한다.
   - 선택 중인 플레이어 A의 이동·점프·로프 입력만 게임에 전달되지 않고, 실제 전투가 반투명 배경으로 식별되는지 확인한다.
3. **피격과 개별 부활**
   - 적 투사체의 로프 절단과 본체 피격을 각각 경험한다.
   - 무엇 때문에 로프가 끊겼고 체력이 줄었는지 별도 설명 없이 인지했는지 기록한다.
   - 한 명의 체력을 0으로 만들고 동료 입력 없이 해당 플레이어만 활성 체크포인트에서 즉시 최대 체력으로 부활하는지 확인한다.
   - 동료 위치·체력·generic Augment loadout과 공용 월드 시간이 그대로 유지되는지 확인한다.
4. **낙사와 개별 부활**
   - 한 명씩 낙사한 뒤 각자 즉시 활성 체크포인트로 복귀하는지 확인한다.
   - 사망·낙사한 플레이어만 최근 도달 Stage 체크포인트로 돌아오고 generic Augment loadout은 유지되는지 확인한다.
   - 다운 대기나 팀 전멸로 오해할 만한 화면·조작 정지가 없는지 기록한다.
5. **재참가**
   - 플레이어 B가 월드에 남은 상태에서 플레이어 A의 연결을 끊는다.
   - 메뉴에 보존된 채널 번호로 플레이어 A가 명시적으로 다시 참가한다.
   - 기존 플레이어 신원 복원이 아니라 새 연결로 현재 월드 스냅샷에 합류하고, 이후 조작과 전투가 정상인지 확인한다.
6. **계속 등반**
   - 남은 시간 중 한 명이 같은 적을 공격하고 다른 기기에서 그 적의 HP 감소를 관찰한 뒤 역할을 한 번 바꾼다.
   - 공격·피격 표현만 보이고 상대 기기의 적 HP가 그대로이거나, 감소한 HP가 이전 값으로 돌아오는 순간이 있는지 기록한다.
   - 남은 시간 동안 다음 Stage 체크포인트 또는 현재 content boundary 방향으로 진행한다.
   - 시작 직후에는 없던 입력 지연·하드 스냅·원격 객체 되감김이 진행 시간에 따라 누적되는지 확인하고, 등반을 지속하기 어려운 구간을 시각과 함께 기록한다.
   - 태블릿과 휴대폰 중 한 기기만 끊기면 같은 시점의 frame interval p95, draw duration p95, dropped steps, CSS/backing 크기와 유효 DPR을 비교한다. 네트워크 RTT가 비슷한데 렌더 값만 나쁘면 클라이언트 렌더 병목으로 분리해 기록한다.

### 네트워크 진단

각 기기에서 세션 종료 직전 디버그 수치 화면의 **진단 복사**를 누르고 결과를 기록에 붙인다. 아직 자동 합격 수치를 정하지 않으며, 체감 문제와 같은 시점의 값을 함께 남긴다.

기본 Sector Runtime의 정상 owner snapshot은 소유자 보정을 하지 않으므로 보정 거리와 하드 스냅은 `0`이어야 한다. 값이 증가하면 허용 가능한 최후 안전장치가 아니라 legacy Area rollback이 잘못 호출됐거나 소유자 보정이 다시 들어온 회귀로 기록한다.

## 판정

### 멀티 동기화 결함의 수치 판정

HP 복구, 로프 재부착, 투사체 중복처럼 상태 정합이 핵심인 결함은 스크린샷이나 VFX만으로 통과시키지 않는다. 재현 시점에 다음 값을 소유 클라이언트, 서버 복제본, 동료 클라이언트 기준으로 기록한다.

- `health`
- `rope.isAttached`와 `ropeDisabledRemaining`
- 충돌한 투사체 ID와 활성 투사체 개수
- pending impact claim과 receipt의 승인 여부
- 입력 종료 뒤 서버·동료가 소유 또는 피해 클라이언트 결과에 수렴했는지

공개 멀티 smoke 통과는 연결과 채널 수명주기의 증거일 뿐 모바일 입력·충돌 판정의 증거가 아니다. 모바일 관련 결함은 최소한 모바일 단독 멀티 경로와 PC·모바일 2인 경로를 구분해 확인한다.

다음을 모두 만족하면 해당 세션을 통과로 기록한다.

- 설명 없이 2분 안에 부착·스윙·해제를 이해하고 로프 이동의 재미를 확인했다.
- generic Augment 선택 중 월드가 멈추지 않으며, 선택 중인 플레이어만 게임 입력이 차단되고 동료는 계속 행동할 수 있다.
- 로프 절단, 본체 피격, 사망·낙사, 개별 체크포인트 부활과 Augment loadout 유지의 원인을 플레이어가 이해한다.
- 재참가 후 같은 월드에서 정상적으로 협동 진행을 이어간다.
- 상대가 공격한 적의 HP가 다른 기기에서도 최신 값으로 감소하고, 새 피해나 회복 규칙 없이 이전 HP로 되돌아가지 않는다.
- 진행 시간이 길어져도 입력 지연·하드 스냅·원격 객체 되감김이 누적되어 핵심 로프 조작과 전투를 지속할 수 없는 문제가 없다.

실패 시 밸런스 수치를 즉시 임의 변경하지 않는다. 월드 시드와 재현 증거를 먼저 남기고, 동일 조건 재현 여부를 확인한 뒤 별도 작업으로 조정한다.
